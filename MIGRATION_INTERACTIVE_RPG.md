# Переход на Chronicles RPG

Новый интерфейс использует структурированные кампании вместо таблицы сообщений.

## Перед запуском

1. Откройте SQL Editor проекта Supabase.
2. Выполните [`migration_interactive_rpg_v1.sql`](./migration_interactive_rpg_v1.sql). Миграцию можно безопасно запускать повторно: она добавит недостающие поля `characters.gold` и `characters.inventory_data`, создаст торговцев и общий сундук, включит realtime для кампаний, обновит кеш схемы API и разрешит удалять героев из библиотеки без удаления сохранённых кампаний.
3. Проверьте переменные окружения:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
   - `VITE_OPENROUTER_API_KEY` — опционально. Без него включается локальная демонстрационная кампания и локальный помощник предыстории.
4. Запустите `npm test`, `npm run typecheck` и `npm run build`.

Миграция не удаляет старые `messages`, `game_sessions`, лобби или персонажей. Старый чат остаётся в репозитории как архив на время переноса, но новый `App` его больше не загружает.

## Реализованный поток

- главный экран: соло, создать партию, войти по коду, герои, продолжить;
- восьмишаговый мастер персонажа;
- структурированная предыстория и три варианта от помощника;
- нулевая сессия с длиной, тоном, сеттингом, сложностью и границами;
- генерация библии кампании и сцен;
- интерактивное чтение без игрового чата;
- условные варианты, проверки d20 и голосование;
- запуск боевого режима из сюжетного выбора;
- инвентарь с ячейками, экипировкой, быстрыми слотами, золотом и переносом старого снаряжения;
- конечный ассортимент торговцев, покупка, продажа и общий сундук партии;
- сохранение сцен, состояния кампании и снимков героев.

## Следующий слой

Полноценный групповой бой пока требует отдельной модели очереди ходов в Supabase. В текущем вертикальном срезе бой из групповой сцены проводит ведущий, после чего результат синхронизируется с кампанией.
